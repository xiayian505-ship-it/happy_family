shift_roster_v1｜櫃檯人員排班紀錄表

這是一份完全獨立的前端版本。
不使用 CDN、不依賴外部套件；HTML / CSS / JS 放在同一資料夾即可使用。

檔案：
- shift_roster_v1.html：頁面骨架
- shift_roster_v1.css：畫面 / 手機自適應 / A4 橫式列印
- shift_roster_v1.js：排班輸入、模式、對話框、月份畫面狀態
- shift_roster_storage.js：localStorage、月份 key、人員 ID、月份資料讀寫
- shift_roster_backup.js：JSON 下載 / 匯入 / 格式驗證 / 歷史月份清理
- shift_roster_rules.js：規則檢查（含跨月連勤、跨月轉班）
- shift_roster_export.js：原生 Canvas 繪製 → PNG → 預覽 / 下載 / 列印

本機資料 key：
- elitehotel:shift_roster:meta
- elitehotel:shift_roster:settings
- elitehotel:shift_roster:employees
- elitehotel:shift_roster:month:YYYY-MM

目前主要功能：
1. 開啟時依裝置本機日期預設顯示「下個月」；年月仍可自由切換並自動跨年。
2. 每個月份獨立保存；第一次建立新月份時，自動沿用相鄰月份的人員姓名、employee ID 與人員班別設定，排班／排休內容保持空白。第一次導入若往回補前月，也可從下一月帶回人員身分。
3. A~F 只是當月班表代號；員工背後使用固定 employee ID，所以跨月即使 C 改成 B，仍可辨認為同一人。
4. 姓名仍直接在班表輸入，不需「新增人員」或「儲存」按鈕。輸入內容即時保存；離開姓名格 / Enter 後才確認 employee ID。
5. 姓名顯示最多取 3 個 Unicode 字元；兩字姓名可保留半形／全形空白做排版。身分比對時會忽略空白，例如「曹操」「曹 操」「曹　操」可視為同一姓名。
6. 日期列兩白兩灰跨月連續；六日粉紅。
7. 週六休假欄預設禁休斜線，可逐日取消。
8. 23~07 週六預設灰底；灰底模式可套用到任一排班格，實際時間可選填。再點已灰底的格子會直接取消；未填時沿用該班別原時間，23~07 灰底使用預設時間 22~06。
9. 粉底：特殊班粉紅底 + 實際時間，下方長條以「A / 12 / │ / 20」直排註記；再點已粉底的格子會直接取消。
10. 假別：公休、特休、請假、例外排休。特休／請假會在下方長條顯示直式備註；請假代號顯示紅字。
11. 開會：指定日期後，下方長條顯示「8 點 櫃 檯 開 會」，不參與工時檢查。
12. 點班別標題可整列填 A~F，之後仍可逐格修改。
13. 點下方姓名區 A~F 可批次排公休：當月日期複選 1~8 天；若某日休假兩格已滿、該員工已排班或已有其他假別，只略過該日，其他日期照常完成，最後列出未排入日期供單格修改。
14. 排班與休假互斥；衝突時選「排班 / 休假」。禁假日單格輸入休假時，可選「例外排休 / 請假 / 返回」。
15. 人員班別：A~F 可複選早班／中班／夜班。早班＝07~15；中班＝15~23、16~00；夜班＝23~07、00~08。
16. 排假檢查只計公休（含例外排休），特休／請假不計入每月公休目標。
17. 規則檢查採逐條提醒、可選例外安排：
    - 禁假日排公休／特休
    - 有效員工未設定人員班別
    - 同組同日多人休假（早／中班組與夜班組）
    - 中班休 → 隔天早班休的相鄰排休順序
    - 特殊班缺少有效實際時間
    - 連續上班超過設定天數
    - 轉班間隔低於設定時數
    - 前月銜接資料不存在／不足
18. 跨月規則按 employee ID 判斷，不按 A~F。連勤會往前讀前月月底；轉班也會比較前月最後工作班與本月第一班。前月不必完整建檔，只需補足月底銜接資料；空白不會被當成休假。
19. 本月清空保留姓名與公休／特休數字，其餘本月資料清掉。
20. 列印／匯出 PNG 前詢問是否加入右上角時間。
21. PNG 使用原生 Canvas，不使用 DOM→SVG foreignObject、不呼叫第三方套件。
22. PNG 檔名：EliteHotel_YYYYMMDD_HHmm.png（日期時間為實際輸出時間）。
23. A4 橫式固定；現階段列印安全邊界仍為 6mm，古董印表機 12mm 安全邊界尚未處理。
24. 全部使用系統安全字體 fallback，不外連字體。

JSON 備份
--------
- 下載檔名：EliteHotel_YYYYMMDD_HHmm.json。
- JSON 為完整備份：包含 schemaVersion、設定、員工 ID 與所有已保存月份。
- 匯入前會先解析並完整驗證格式；不是 EliteHotel 班表格式、版本不支援或月份結構錯誤時直接拒絕，不修改任何現有資料。
- 格式驗證成功後才會顯示覆蓋警告，並提供「取消 / 確認匯入」。
- 確認匯入後採整包覆蓋，不做資料比對或合併；提交失敗時嘗試回復匯入前資料。
- 「進階資料管理」預設收合，可手動選擇截止月份並清除更早的歷史月份；不做自動刪除。

本機保存注意：
- 一般使用會自動寫入 localStorage，不需另按儲存。
- 若瀏覽器環境無法使用 localStorage，程式會明確警告；該次仍可操作，但重新整理後可能失去資料，建議下載 JSON。
- 本機資料不保存 PNG、圖片、Blob 或其他大型檔案，主要為純文字 / 數字 / 布林資料。
- 正式單機使用若以 file:// 直接雙擊 HTML，建議固定主 HTML 檔名與資料夾位置；JSON 才是可攜式備份。
